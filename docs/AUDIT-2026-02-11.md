## Overall Health Assessment

**Grade: B-** — The app is functional and well-structured at a high level, with clean Zustand stores, a solid component hierarchy, and good feature coverage. However, it has significant gaps in error handling, performance optimization, accessibility, and PWA capabilities that would need addressing before a production-quality release.

### Strengths
- **Clean architecture**: Stores are well-separated (auth, player, UI, archive, toast)
- **Good TypeScript usage**: Few `any` types, consistent interfaces, proper SDK typing
- **Feature-rich**: Scrobbling, EQ, sleep timer, radio mode, offline cache, keyboard shortcuts
- **Dual-source model**: Jellyfin + Archive.org integration is well-separated
- **Responsive design**: Mobile + desktop layouts throughout

### Weaknesses
- **No error boundaries** — any render error crashes the entire app
- **No route-level code splitting** — full 13k-line bundle on first load
- **Audio engine fragility** — stale closures, EQ one-shot issues, no error recovery
- **No real PWA support** — offline cache exists but no service worker to use it
- **Accessibility** — largely unusable with screen readers or keyboard-only

## Top Priority Fixes

### 1. Add Error Boundaries (#65)
Single highest-impact fix. Without this, any unexpected API response or render error kills the entire app with no recovery.

### 2. Fix Audio Engine Stale Closures (#66, #75)
The audio engine is the core of the app. The stale closure issues and EQ one-shot problem can cause playback failures. Consider reusing a single `<audio>` element instead of creating new ones per track.

### 3. Fix Playback Reporting (#79)
Quick fix — change one line to read from `lastReportedTimeRef.current` instead of the stale `currentTime` closure. Currently reports wrong position to Jellyfin.

### 4. Add Route-Level Code Splitting (#67)
Low-effort, high-impact performance win. Just wrap `lazy()` + `<Suspense>` around page imports.

## Architecture Recommendations

### Audio Engine Refactor
The current approach of creating new `Audio()` elements per track is the root cause of multiple bugs (EQ breaking, gapless issues, cleanup complexity). Recommend:
- Use a single persistent `<audio>` element, change `src` on track change
- Keep a second `<audio>` element only for crossfade/gapless preload
- Move all audio state to refs to avoid stale closures

### State Management
- **Player store** is well-designed but persists too much data. Slim down the persisted queue.
- **Archive store** is clean and appropriate.
- **UI store** is a catch-all — consider splitting scrobble settings into their own store.
- Consider React Query or SWR for API data caching instead of local state in each page.

### API Layer
- Add a centralized request wrapper with: abort controllers, retry logic, error normalization
- Cache API responses (even 60-second TTL would help)
- The Archive.org and Jellyfin APIs should have consistent error handling patterns
